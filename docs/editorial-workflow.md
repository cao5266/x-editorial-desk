# X 选题、核验与审稿手册

## 1. 采集只产出线索

- **Freebie Radar**：发现实用工具、社区新项目、免费额度和优惠线索；既有 AI 审核结果仅供初筛。
- **Miniflux**：看项目发布记录、官方博客和维护者文章；跳过例行构建、重复版本和没有实际用途的变更。
- **changedetection.io**：看官方页面、价格与权益条款的实质变化；排除首次快照、相对日期、计数器和排版噪声。

建议先看近 24 小时，48 小时补漏。记录原始发布日期、实质变更日期（如有）与采集时间；按「项目／权益 + 事件 + 版本或生效日期」跨源合并，保留正式来源。超过窗口的好材料可进常青池；使用「仍可领取」等时效措辞前重新查官方条款。此处是编辑规则，不代表三个服务已经接入统一选题池或需要改它们的配置。

## 2. 选题卡必须能落到行动

先写一张卡：**栏目｜受众｜解决的任务｜读者第一步｜一手链接和核验日期｜验证状态｜限制／成本｜配图类型**。缺少用途或第一步，不进入起草；缺少影响读者选择的关键事实，补证据或暂缓。

| 栏目 | 核验重点 | 推荐配图 |
| --- | --- | --- |
| 实用工具 | 官方功能、使用入口、计划／平台限制；能否用一个无敏感数据的样例演示。 | 脱敏界面截屏、输入→输出示意；没有实测就不用结果对比图。 |
| 开源／工作流 | 原仓库、相关版本、许可证（若声称开源）、运行环境、依赖、是否要密钥或付费。不要把「可看源码」等同于开源。 | 最短流程图、终端或结果截图；说明版本和条件。 |
| 免费权益 | 官方领取入口、身份及地区资格、额度和周期、领取期限或用完即止、绑卡、到期／超额／自动续费规则。不能确认免扣费时，不写「零成本」。 | 「谁能领／能领多少／何时到期」条件卡，或带核验日期的官方条款截图。 |

安全事件不是独立栏目。即使原文可核验，也要能转成与账号定位相符的、可照着做的工具或工作流指南，才值得继续；否则不主推。

## 3. 证据与文案分开审

- **已实测**：保留环境、版本、日期、输入与实际结果。测试成功只覆盖该场景，不外推所有网页、账号或方案。
- **官方说明，未实测**：可写文档明确支持的能力和官方步骤，正文写「官方说明，未实测」；用「可以先用……试」而非「我用它成功……」。同一家公司发布的公告和文档不算两份独立实测。
- **待核验**：打不开一手来源、功能边界不清楚，或无法确认权益是否仍有效。暂存；除非删除相关说法仍能给读者明确价值，否则不交待发布定稿。

短帖顺序：**能做什么 → 怎么开始 → 限制或未实测标注 → 一手链接**。串帖顺序：**具体场景 → 前置条件 → 最小上手路径 → 已知限制与来源**。配图用来解释步骤、条件或结果，不重复堆文字；图上数字、套餐和状态也要逐项对原文。无增量就不配图。

## 4. 用现有候选做尺度校准

- **OpenRouter 数据事件**：保留为资料，不作为这批主推。若以后有适合读者的切口，可另做「如何核对模型请求走哪家供应商」的工作流；把官方步骤和实测结果分开，不把事件重新包装成新闻。
- **Lindy 浏览器操作**：保留为工具候选。优先讲一个具体任务，例如用测试表单演示「打开页面 → 填写样例 → 检查结果」。尚未跑过时写「官方说明，未实测」；MCP 管理任务和网页操作是两个能力，不能合写成「从 MCP 操作任意网页」。
